## 1. 캐릭터·몬스터

사용자가 플레이어와 몬스터의 2D 스프라이트를 AI로 제작해도 된다고 지정했다. 플레이어·일반·공중·보스의 외형은 같은 화풍과 시점으로 맞추고, 투명 배경·일관된 픽셀 밀도·바닥 기준점을 적용한다. 공격 무기와 효과는 본체 그림에 합치지 않는다. 본체의 단일 스프라이트를 기울이고 상하 이동시키며, 별도의 걷기·공격 프레임 제작을 전제로 하지 않는다.

생성 시 사용한 프롬프트·원본 위치·도구·제작일과 게임에 반영한 파일을 에셋 기록에 남긴다. 생성 결과는 배경 투명성, 축소 시 실루엣, 몬스터 종류 구분, 피격 색과 팽창 후 복귀를 실제 화면에서 확인한 뒤 사용한다. 사용자가 제공한 두 참고 이미지는 표현 참고이며 완성 에셋으로 복사하지 않는다.

**추천 출발점은 무료 Slash Effect Collection + Fire Spells Effects VFX Pack 조합이다.** 구성상 필요한 역할을 나눌 수 있다는 판단이며 최종 외형 승인을 뜻하지 않는다. 원본 프레임 수·캔버스·여백을 확인하고, 작은 캐릭터와 함께 표시했을 때의 선 굵기·픽셀 밀도·투명도를 맞춘다. 실제 도끼의 한 바퀴와 창의 찌르기 길이는 게임의 궤적에 맞게 조정해야 한다.

원본 사이트가 열려 있다는 이유만으로 전체 팩을 무료로 취급하지 않는다. 도입 시 출처·제작자·취득한 버전/파일·라이선스·크레딧 조건을 기록하고, 원본 파일은 해당 조건에 맞춰 보관한다. 에셋의 기본 피해 스크립트·콜라이더·애니메이션 이벤트가 게임 피해를 추가로 발생시키지 않게 한다.

공격의 기준은 기존 `AttackShapeSnapshot`이다. 에셋은 이 데이터의 방향·위치·진행률·반경을 읽어 재생한다. 검 60도, 창 길이, 도끼 회전, 폭발 반경의 실제 범위는 반투명 표시로 유지하며 장식 잔상과 별도로 읽을 수 있어야 한다. 에셋 도입 때문에 공격 판정이나 강화 효과를 바꾸지 않는다.

## 3. 경험치 외형과 수집

작은 원형의 밝은 중심과 같은 색의 부드러운 외곽 빛 번짐을 기본으로 한다. 색은 초록·파랑·빨강 순으로 경험치가 많음을 뜻한다. 실제 바닥을 비추는 개별 광원은 필수 기능으로 추가하지 않으며, 먼저 구슬 자체가 빛나는 느낌을 만든다. 많은 구슬이 겹쳐도 주변 적·공격 범위를 가리지 않도록 크기와 번짐을 조정한다.

논리 흐름은 `Grounded → Attracting → Collected`다. 접근은 흡수 시작 조건이고 몸 접촉은 실제 경험치 증가 조건이다. 한 번 흡수되기 시작하면 이동 중인 플레이어를 계속 따라가며, 표시 애니메이션의 종료 콜백이 경험치를 직접 더하지 않는다. 화면 밖·표시 풀 회수·재시작에서도 같은 규칙을 지킨다.

색은 보존한 실제 경험치 값에 따라 결정하고, 색에 맞추려고 드롭 값을 반올림하거나 줄이지 않는다. 값과 등급 구분선은 설정으로 분리한다. 임시 시각 검증에서는 1·5·25 값을 배치해 초록·파랑·빨강을 함께 확인하며, 이는 몬스터 종류별 드롭량이나 최종 밸런스를 새로 확정한 값이 아니다.

## 4. 구현과 확인 위치

- A3: 경험치 ID·값·위치와 대기/흡수/획득 상태를 보존하는 데이터 계약.
- C1: 근접 시 흡수 시작, 현재 플레이어 위치 추적, 접촉 후 한 번만 지급, 사망/이전 판 지급 거절, low AI 목표 갱신.
- D2: AI 스프라이트 제작·외부 공격 에셋 도입·구슬 3색 발광·비행 표시·풀 초기화·실제 화면 확인.
- D3: 구슬 밀집과 흡수 중 화면 이탈·청크 이동·재시작을 포함한 통합/성능 확인.

현재 문서는 조사와 계획이다. 생성 결과, 구매/다운로드 기록, 게임 실행 성공을 대신하지 않는다.
