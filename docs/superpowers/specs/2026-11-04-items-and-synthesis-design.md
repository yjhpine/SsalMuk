## 1. 사용자 확정 사항과 이번 범위

- 이번 후속 작업은 아이템 기획, 상자 보상·UI, 합성이다. 별도 생존 AI 검사·조정은 제외한다.
- 색상과 명칭: 회색 커먼 → 초록 언커먼 → 파랑 레어 → 노랑 레전더리 → 빨강 얼티밋.
- 상자 아이템 후보 3개 중 1개를 선택한다. 아이템 이름은 마우스를 올린 툴팁에서 해당 등급 색상으로 보인다.
- 왼쪽에 강화 내역, 오른쪽에 획득순 아이템을 왼쪽→오른쪽, 위→아래로 배치한다.
- 같은 등급의 아이템 3개를 선택해 한 단계 높은 무작위 아이템을 얻는다. 동일한 아이템 여러 개도 재료로 허용한다.
- 확정 합성은 지정 재료 조합으로 지정 결과 아이템을 얻는 레시피 방식이다.
- 사용자는 능력치 + 고유 효과 혼합형을 선택했다. 하위 등급은 기본 능력치, 상위 등급은 고유 효과를 중심으로 구성한다.
- 화면 목업 대신 문서로 정리하기로 했다. 컴퓨터 유즈는 사용하지 않는다.

### 접근 방식 비교

1. 능력치만 강화: 구현과 수치 조정이 단순하지만 기존 레벨업 강화와 역할이 크게 겹친다.
2. 능력치 + 고유 효과: 기존 능력치와 함께 흡혈·번개·폭발 같은 효과가 있어 합성 목표마다 전투 방식이 달라진다. 사용자가 이 방식을 선택했다.

기술 구조는 기존 프로젝트를 확장한다. 영구 아이템은 현재의 바닥 일시적 버프와 구분하고, 기존 무기·레벨업을 새로 만들지 않는다.

## 2. 제안하는 운영 기본값

이 절부터의 세부값은 작성자가 제안한 초기값이다. 사용자가 확정한 것으로 기록하지 않는다.

- 아이템은 보유 즉시 적용되는 패시브이며 별도 장착 칸은 없다. 새 판·사망 때 모두 초기화한다.
- 보유 개수에 게임 규칙상 상한을 두지 않는다. 같은 아이템도 각각 소유하며 능력치 보너스는 합산한다.
- 동일 고유 효과 계열은 하나의 발동기로 합친다. 피해·회복·보호막의 양은 합산하되 복사본마다 별도 투사체·폭발을 만들지 않는다.
- 상자 선택과 합성 중에도 전투는 계속된다. ESC 일시정지 중에는 획득·합성 적용과 발동 시계가 멈춘다.
- 합성은 수동, 성공률 100%, 추가 재화 비용 없음. 재료 3개를 소모하고 결과 1개를 지급한다. 재료 효과는 사라지고 결과 효과만 남는다.
- 얼티밋은 최고 등급이므로 일반 합성 재료로 사용할 수 없다. 이번 레시피도 한 단계 상승만 포함한다.
- 레시피가 맞으면 결과를 미리 보여주는 '확정 합성' 버튼을 활성화한다. 같은 재료를 '랜덤 합성'에 쓰는 선택도 허용하며, 레시피가 일치한다는 이유로 임의로 확정 합성하지 않는다.
- 합성으로 생긴 아이템은 새로운 획득으로 보고 오른쪽 목록의 맨 뒤에 놓는다. 재료는 목록에서 제거하고 나머지 아이템의 상대 순서는 유지한다.

### 계산·중복 규칙

- 아이템 능력치의 같은 항목은 보유분을 선형 합산한다. 공격력·공속·이속·흡수 반경은 기존 성장 계산 결과에 (1 + 아이템 보너스 합)을 곱한다. 공속 보너스는 공격 주기를 그 배율로 나눈다. 회복은 기존 초당 회복에 더한다. 이 규칙을 툴팁에서도 '현재 성장에 추가 배율'로 일관되게 설명한다.
- 경험치는 기존 공용 강화의 퍼센트에 아이템 경험치 퍼센트를 더한다. 현재 1/100 정수 단위 누적을 유지하며 중간 반올림·버림을 하지 않는다.
- 흡혈 비율과 1회 회복 상한은 보유분을 더한다. 실제 회복은 최대 체력을 넘지 않는다. 피해를 주지 못한 타격과 이미 죽은 적에는 발동하지 않는다.
- 번개·폭발 피해 계수는 보유분을 더한다. 번개의 연결 수·연결 거리, 폭발 반경은 보유한 해당 계열의 최고 등급 값을 사용한다. 발동기와 간격은 계열당 하나다.
- 번개는 각 연결마다 범위 안에서 가장 가까운 살아 있는 적을 고르며 거리 동률은 유닛 ID 순이다. 원래 피격 적과 이미 연쇄로 맞은 적은 제외한다. 후속 대상이 없으면 종료한다.
- 번개와 폭발은 별도 이동 투사체 없이 해당 발동 순간에 피해를 처리하고 짧은 시각 효과를 표시한다. 지형을 통과하는 기존 공격 계약을 유지한다.
- 아이템의 파생 피해는 다른 아이템 고유 효과를 재발동시키지 않는다. 파생 피해로 적을 처치하면 기존 처치 수·경험치·버프 드롭은 정상 지급한다. 기본 파이어볼 폭발은 기존 무기의 직접 공격으로 취급한다.
- 아이템 효과의 연결 거리·폭발 반경·발동 간격은 그 아이템 정의를 따른다. 기존 무기 개수·범위 강화나 일시적 무기 범위 버프가 아이템 발동 수·반경을 추가로 늘리지는 않는다.
- 보호막 용량은 보유분을 더하고 재충전 간격은 해당 계열의 최고 등급 값을 쓴다. 무적 판정을 통과한 피해를 보호막부터 차감하며 남는 피해만 체력에 적용한다. 보호막에 막힌 유효 피격에도 기존 피격 표현·짧은 무적·넉백은 유지한다.
- 처음 보호막을 얻으면 최대치로 시작한다. 이후 획득·합성으로 용량이 바뀌어도 기존 잔량을 새 최대치 이하로 유지하며 즉시 다시 채우지 않는다. 계열이 완전히 사라지면 잔량·시계를 초기화한다. 합성은 원자적으로 적용하여 재료 제거 순간을 별도 무소유 상태로 취급하지 않는다.
- 고유 효과는 가장 오래된 유효 직접 적중 이벤트부터 처리하고 같은 계열 간격 안의 추가 타격은 적립하지 않는다. 수량 변경으로 간격을 우회하지 않도록 계열 발동 시각을 보존한다.

## 4. 확정 레시피 18개

입력 순서는 무관하며 수량을 포함한 조합이 정확히 맞아야 한다. 표의 모든 레시피는 같은 등급 재료 3개를 소모하고 바로 다음 등급 1개를 만든다.

| 재료 | 확정 결과 |
| --- | --- |
| 무딘 칼날 ×2 + 작은 깃털 | 강철 문장 |
| 작은 깃털 ×2 + 낡은 신발 | 매의 깃털 |
| 낡은 신발 ×2 + 지식 파편 | 바람 신발 |
| 약초 잎 ×2 + 무딘 칼날 | 생명 약초 |
| 자석 조각 ×2 + 낡은 신발 | 자석 핵 |
| 지식 파편 ×2 + 약초 잎 | 지식의 서 |
| 강철 문장 + 생명 약초 + 바람 신발 | 흡혈 송곳니 |
| 매의 깃털 + 자석 핵 + 지식의 서 | 번개 핵 |
| 강철 문장 + 매의 깃털 + 자석 핵 | 불씨 심장 |
| 생명 약초 + 바람 신발 + 지식의 서 | 수호 부적 |
| 흡혈 송곳니 ×2 + 불씨 심장 | 혈월 이빨 |
| 번개 핵 ×2 + 흡혈 송곳니 | 폭풍 핵 |
| 불씨 심장 ×2 + 번개 핵 | 화염 심장 |
| 수호 부적 ×2 + 흡혈 송곳니 | 성채 문장 |
| 혈월 이빨 ×2 + 화염 심장 | 불멸의 심장 |
| 폭풍 핵 ×2 + 혈월 이빨 | 뇌신의 왕관 |
| 화염 심장 ×2 + 폭풍 핵 | 태양의 핵 |
| 성채 문장 ×2 + 혈월 이빨 | 영원의 방패 |

상기 표는 6+4+4+4=18개다. 동일 재료 3개는 일반 랜덤 합성에 사용할 수 있다. 확정 레시피가 없는 조합에는 확정 버튼을 활성화하지 않는다.

## 5. 상자 등급·선택권

- 초기 등장 확률 제안: 커먼 65%, 언커먼 25%, 레어 8%, 레전더리 1.8%, 얼티밋 0.2%. 시간에 따라 바뀌지 않는 데이터 값으로 시작한다.
- 상자의 색이 보상 등급이다. 그 등급의 서로 다른 아이템 3종을 중복 없이 뽑고 1개를 고른다. 이미 보유한 종류는 다시 나올 수 있다.
- 상자 위치·개봉 상태 보존, 도달 조건, 방향 화살표, 근처 경험치를 먹으며 상자로 향하는 AI는 유지한다. 등급은 판 시드와 청크 좌표로 결정하고 재방문해도 바뀌지 않는다.
- 등급 난수는 기존 위치 난수에서 분리한다. 아이템 후보·합성 난수도 기존 맵·소환·레벨업 난수와 분리한다. UI를 열거나 툴팁을 띄우는 일은 난수를 소비하지 않는다.
- 개봉 순간 상자 ID·등급·3개 후보를 가진 별도 선택권을 한 번 생성한다. 여러 상자를 열면 개봉 순서로 보관하며 레벨·경험치는 올리지 않는다.
- 이미 화면에 표시된 선택은 끝날 때까지 유지한다. 이후 대기 중인 상자 선택을 먼저, 그 뒤 레벨업 선택을 표시한다. 레벨업과 상자 화면을 겹쳐 표시하지 않는다.
- 기존 5초 AUTO는 레벨업만 대상으로 유지한다. 상자는 수동이다. 상자가 표시되는 동안 숨겨진 레벨업 선택의 AUTO 시계는 진행하지 않으며 다시 표시되면 5초를 새로 센다.
- 선택 확정은 판 ID·선택권 ID·후보 번호를 검증한 뒤 고정 주기에서 한 번 적용한다. 중복 클릭·이전 판 요청·ESC 정지·사망 이후 요청에는 지급하지 않는다.
- 기존 상자 '강화 3개' 임시 경로는 새 아이템 보상으로 교체한다. 기존 무기·공용 레벨업 선택은 유지하며 상자 개봉으로 양쪽 보상을 동시에 주지 않는다.

## 6. UI 동작

- 기존 런타임 uGUI, 기존 폰트·다크 배경을 유지한다. 씬에 게임 개체나 UI를 사전 배치하지 않는다.
- 왼쪽 강화 패널: 시작/보유 무기별 공격력·개수·공속·범위 강화 단계와 공용 이속·회복·수집·경험치 단계를 묶어 표시한다. 아이템 보너스를 레벨업 단계로 잘못 합치지 않는다.
- 오른쪽 아이템 패널: 한 줄 4칸을 기본값으로 하고 획득순으로 배치한다. 동일 아이템도 개별 칸이다. 길어지면 세로 스크롤하며 보유 데이터에는 제한을 두지 않는다. 보이는 행과 여유 행만 재사용한다.
- 칸에는 구분 가능한 작은 심볼과 등급 테두리를 표시한다. 첫 구현은 기존 스타일에 맞는 간단한 아이콘이며 신규 외부 에셋 구매·설치는 없다.
- 상자 보상 카드·보유 칸·레시피 결과의 공통 툴팁: 이름(등급색), 등급명, 현재 아이템 효과, 해당 재료의 조합 정보를 표시한다. 설명은 밝은 기본색으로 읽기 쉽게 둔다.
- 색상 초기값: 회색 #B8BEC7, 초록 #70D66B, 파랑 #62B0FF, 노랑 #FFD75A, 빨강 #FF6571. 상자와 카드 테두리·이름에 같은 색상 표를 사용한다.
- 오른쪽 '합성' 버튼으로 하단 패널을 연다. 아이템 칸을 눌러 재료 3개를 선택·해제하고 선택 테두리와 재료 칸을 표시한다. 동일 소유 개체를 두 번 고를 수 없다.
- 랜덤 결과는 다음 등급과 가능한 결과 목록을 보여주며 확정된 결과인 것처럼 이름을 노출하지 않는다. 레시피가 맞으면 지정 결과의 이름·아이콘·효과를 미리 보여준다.
- 합성 실행 전 '선택한 재료 3개와 효과가 사라짐'을 패널에 상시 표시한다. 실행 버튼 외에 매번 별도 확인 팝업을 추가하지 않는다.
- 부족한 재료·다른 등급 혼합·최고 등급·없는 레시피는 버튼을 비활성화하고 이유를 표시한다. 서버가 아닌 로컬 게임이어도 Core에서 동일 조건을 재검증한다.
- 상자/레벨업 선택이 나타나면 합성 입력을 잠시 숨겨 충돌을 막는다. 기존 재료 선택은 ID로 기억하되 다시 보일 때 유효성을 확인한다. 전투와 화면 밖 몬스터는 계속 진행한다.
- 마우스 클릭으로 레벨업 AUTO가 해제되는 기존 규칙은 아이템·합성 클릭에도 유지한다.

## 7. 내부 연결과 불변 조건

- 기존 바닥 버프는 PowerupRecord/RunModel.Items, 영구 패시브는 별도 ItemInventory로 구분한다. 자석·무적·이속·범위 10초 버프를 인벤토리 아이템으로 바꾸지 않는다.
- 아이템 정의는 고정 ID, 표시 이름, 등급, 능력치 보너스, 효과 계열·계수로 구성한다. 레시피는 정의 ID와 수량의 다중집합, 결과 정의 ID다. 표시 이름을 데이터 키로 사용하지 않는다.
- 보유 인스턴스는 판 내 단조 증가 ID·정의 ID·획득 순서를 가진다. 아이템 인벤토리 버전은 획득/합성 완료마다 한 번 증가한다.
- 기존 GameCatalog/DevelopmentDefaults 계열에 아이템 정의와 조정값을 연결하고, 판 시작 시 Core 카탈로그로 검증·복사한다. 정의 ID 중복, 빠진 단계, 후보 3종 미만, 잘못된 레시피는 개발 단계에서 명확한 오류로 거절한다.
- ItemRewardService는 상자 선택권을, FusionService는 합성 요청을 담당한다. 기존 RewardService는 레벨업을 담당한다. Presenter는 두 종류의 현재 선택과 합성창 표시만 조정한다.
- 합성 요청은 판 ID·인벤토리 버전·서로 다른 인스턴스 ID 3개·방식·기대 레시피 ID를 포함한다. 실제 소유권·등급·수량·레시피를 고정 주기에서 다시 검증한다.
- 검증 실패나 수치 표현 범위 초과에는 아무 재료도 소모하지 않고 난수도 진행하지 않는다. 성공하면 제거 3개·추가 1개·능력치 캐시 갱신을 원자적으로 한 번 적용한다. 같은 판·인벤토리 버전의 중복 요청을 적용하지 않는다.
- 한 주기의 입력은 레벨업/상자 선택 → 합성 순으로 적용한다. 앞선 획득으로 버전이 바뀐 합성 요청은 거절하며 UI에서 최신 재료 상태를 다시 보여준다.
- 능력치 캐시는 인벤토리 변경 때만 갱신하고 매 프레임 전체 보유 목록을 순회하지 않는다. UI도 인벤토리/강화 버전 변화와 실제 화면 표시 행만 갱신한다.
- DamageRequest/CombatEvent에 직접/아이템 파생 출처와 실제 체력 감소량을 전달한다. 기존 호출의 기본 동작을 보존하고 Contact 피해는 플레이어 소스 조건에서 제외한다.
- ItemEffectSystem은 직접 피격 이벤트를 받아 한 주기 큐로 처리한다. 기존 DamageService의 중복 방지·사망·넉백을 우회하지 않으며 발동 공격 ID는 처리가 끝나면 완료한다.
- 한 고정 주기는 입력 → 버프/보호막 시간 → AI/이동 → 상자 개봉 → 무기 공격 → 아이템 효과 → 사망 정리 → 접촉 피해 → 경험치 수집·선택 갱신 순으로 연결한다. 직접 사망 이벤트의 위치와 피해량은 삭제 전 스냅샷으로 보관한다.
- 실제 게임 규칙은 바꾸지 않는 표현 풀을 사용한다. 번개/폭발에는 개별 Update·Rigidbody·상시 Collider를 붙이지 않는다. 효과가 겹칠 때 시각 효과만 합치거나 재사용하며 피해를 임의로 누락하지 않는다.
- 무한 보유·성장은 기존 숫자 표현 한계 처리를 따른다. 오버플로/NaN/Infinity를 조용히 적용하지 않으며 안전한 실패는 현재 소유 상태를 보존한다.

## 8. 구현 단위와 검증 경계

이 문서 확인 후 상세 구현 계획을 작성한다. 큰 순서는 다음과 같다.

1. 아이템 정의·보유·능력치 계산·레시피 검증과 원자적 합성.
2. 상자 등급·후보·선택권과 기존 레벨업/AUTO 병행.
3. 왼쪽 강화/오른쪽 아이템·툴팁·합성 패널.
4. 흡혈·번개·폭발·보호막과 풀링 표시, 실제 아이템 동작 확인.

필수 검증:

- 동일 아이템 3개, 서로 다른 3개, 동일 인스턴스 중복 선택, 혼합 등급, 얼티밋, 없는 재료/레시피, 중복 실행, 이전 판·버전 요청에서 소모/지급이 정확한지 확인한다.
- 레시피 18개의 입력 순서 독립성·정확한 수량·다음 등급을 확인한다. 실패 시 재료/난수 보존과 합성 후 재료 효과 제거·결과 효과 적용을 확인한다.
- 레벨업·상자 선택권이 서로를 덮어쓰지 않고 상자 등급과 후보가 보존되는지, AUTO가 상자에 적용되지 않는지 확인한다.
- 기존 무기 성장·이속·회복·경험치 소수 처리와 버프를 보존하면서 아이템 보너스가 실제 계산과 UI에 일치하는지 확인한다.
- 각 고유 효과의 유효 타격·발동 간격·중복 계열 통합·파생 재발동 방지·사망 보상·일시정지·초기화, 보호막과 무적/넉백 순서를 확인한다.
- 실제 게임 화면에서 등급별 이름색, 툴팁 경계, 획득순/스크롤/재료 선택/결과 미리보기/빠른 중복 클릭을 확인한다. 전투가 실제로 진행하는 상태인지 별도로 확인한다.
- 원시 결과는 Logs/Validation에 저장하고 현재 소스 manifest/receipt/XML을 대조한다. 전체 회귀·새 빌드·30분 플레이·별도 생존 AI 조정·푸시는 자동 수행하지 않는다.

## 9. 최종 확인 대상

사용자는 혼합형과 레시피 방식, 등급 명칭, 같은 종류 재료 허용까지 확인했다. 남은 확인은 이 문서가 제안하는 24종·18레시피·보유 즉시 적용/중복 통합·재료 효과 소멸·최고 등급 처리·상자 확률을 첫 구현 기본값으로 사용할지다. 수치는 별도 데이터로 두어 추후 조정할 수 있다.

독립 구현 준비 검토 결과: 중요한 추가 질문 없음. 문서의 데이터 개수·형식은 확인했으며 런타임 구현과 검증은 아직 진행하지 않았다.
