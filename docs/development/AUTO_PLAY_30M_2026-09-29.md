## 확인된 병목과 아직 모르는 부분

1. **28분 웨이브 직후 게임 루프에 긴 계산이 몰렸다.** 실제 1,684~1,687초에 433/547/472/467/417/404ms 프레임이 연속 기록됐다. 지연된 카운터의 인접 프레임을 대조하면 Main Thread 약 541.94ms 중 PlayerLoop 약 535.68ms인 표본이 있다. 이때 게임 시계가 한 프레임에 약 0.32~0.34초씩 전진하는 따라잡기 갱신도 관측된다. 그 구간의 일반 수는 약 290에서 14까지 감소하며 처치가 몰렸다. 이 자료만으로 정확히 어느 Core 함수가 첫 지연을 일으켰는지는 분리할 수 없다.
2. **전투 고정 갱신의 임시 메모리 생성이 많다.** 12초 상세 기록 557프레임·606회 FixedUpdate에서 해당 콜백이 164,782,532바이트를 할당했다. 호출당 약 271,918바이트이며 전체 관측 할당의 81.61%다. 표시 LateUpdate는 프레임당 약 49,099바이트다. 전체는 약 16.04MiB/초다. 상세 기록의 시간 비용은 계측 영향을 받으므로 기본 FPS와 섞지 않는다.
3. **메모리 회수에 의한 순간 지연도 실제 확인됐다.** 상세 기록 65번 프레임은 86.28ms이고, `GarbageCollector.CollectIncremental` 53.02ms 안에 `GC.Collect` 32.76ms가 포함된다. 부모·자식을 더하지 않는다. 28분 최대 지연 구간과는 별도 표본이므로 모든 547ms 멈춤이 GC 때문이라고 단정하지 않는다.
4. **몬스터 밀림만을 주원인으로 지목할 근거는 없다.** 이번 상세 기록은 BattleRunner의 고정 갱신·표시까지 구분하며, AI·이동·군중·근접 적중·접촉·수집 각각의 시간을 분리하지 않는다. 표시 비용, Editor UI, 검증 도구의 상태 저장도 함께 관측되지만 모두를 하나의 원인으로 합치지 않는다.

기존 코드와 대조한 우선 조사 지점은 `MeleeAttack`의 반복 공간 조회와 적중 계산, `SpatialIndex.QueryCircle` 반환 목록/래퍼 생성, `ContactDamageSystem`의 매 주기 목록·접촉 구간 생성, 경험치 표시 반환 시 `ExperienceView.ResetVisuals`의 재그리기다. 이들은 후보이며 각자의 정확한 기여율은 아직 측정하지 않았다. 먼저 28분 웨이브와 커진 공격 범위를 짧게 재현하고 구간별 비용·할당을 분리한 뒤, 재사용 버퍼와 불필요한 재그리기를 수정·비교하는 것이 다음 단계다. 적·경험치 삭제, 성장 제한, 공격 생략으로 부하를 숨기지 않는다.
