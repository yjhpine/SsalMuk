# 실제 플레이·밸런스 조정

2026-09-17 시작. 기본 기능 구현 후 사용자가 추가 검사를 종료하고 다음 단계로 진행하도록 지시했다. 새 장시간 자동 검사나 전체 재검사를 시작하지 않는다. 현재 수치는 임시 출발값이며 실제 플레이의 체감에 따라 조정한다.

## 플레이 시작

Unity의 `Assets/_SsalMuk/Scenes/MainMenu.unity`에서 Play → `GameStart`로 시작한다. 이동·공격·경험치 수집은 AI가 담당하고 사람은 레벨업 선택지만 누른다. 선택 중에도 전투는 계속된다. 2026-09-22 공통 추적·보스 돌진은 Unity 프로젝트에 적용됐다. 기존 Windows 실행 파일·ZIP은 2026-09-18 성장·웨이브까지 포함하며 이번 변경은 새로 빌드하지 않았다.

## 조정 순서

1. AI 운영: 경험치를 적극적으로 수집하는지, 접촉 위험을 피하는지, 포위에서 한쪽으로 돌파하는지를 실제 플레이에서 판단한다. 막히는 행동을 체력 증가로 덮지 않는다.
2. 초반 난이도·성장: 첫 선택이 늦거나 연속으로 너무 많이 뜨는지, 검만 가진 초반이 지나치게 답답한지 확인하고 해당 수치 묶음만 바꾼다.
3. 무기 체감: 검·창·도끼·파이어볼의 거리와 주기, 추가 무기와 연속 공격의 느낌을 비교해 조정한다.
4. 시인성: 몬스터 군집, 반투명 범위, 피격, 발광 구슬이 서로 가리지 않게 표시 크기·강도를 조정한다.

AI 세부 판단값은 현재 `Assets/_SsalMuk/Core/AI/AiSettings.cs`와 각 상태에 있다. 에셋에서 바로 바꿀 수 있는 값으로 오인하지 않는다. 기본 운영 규칙과 5분 보스, 무기 4종·강화 5종, 무한 성장, 일반·보스·경험치 보존은 유지한다. 공중의 돌진 후 퇴장은 사용자가 정정한 별도 규칙이다.

2026-09-17 후속 요청으로 일반 몬스터의 맵 전체 상한을 추가하고, 같은 날 추가 지시로 임시값을 300에서 500으로 올렸다. 이미 생성된 적은 유지하고 한도가 찼을 때 추가 일반 소환만 건너뛴다. 막힌 생성의 예약도 빈자리 수까지만 유지한다. 처치로 자리가 나면 다음 일정부터 소환하며, 쉬는 동안의 일반 소환을 몰아서 따라잡지 않는다. 임시 500은 성능 보증이나 최종 밸런스 수치가 아니다. 세부 능력치와 난이도 조정은 이후에 진행한다.

플레이어와 모든 몬스터의 바닥 그림자는 제거했다. 실제 Unity의 300·500마리 비교는 공격·처치 없이 개체 수를 유지한 밀집 진단이며 일반 생존 플레이와 구분한다. 비교 수치와 다음 개선 후보는 [작업 로그](../../log.md)를 따른다.

후속 승인으로 몸통과 몬스터 피격 영역을 분리했다. 원형 기준은 표시 스프라이트의 짧은 변이며 2026-09-18부터 몬스터 몸통 100%, 플레이어 몸통 80%·피격 110%다. 강제로 서로 밀어내던 반복 보정은 없애고 약한 이동 회피를 적용한다. `crowdAvoidanceStrength`는 회피 정도, `bodyRadius`는 지형·접촉, `hurtRadius`는 무기 적중, `visualFootOffset`은 기존 발 위치를 조정한다. 1,000마리는 별도 진단 조건이며 실제 일반 상한은 500이다.

2026-09-18 AI 조정: 수집할 경험치가 없으면 가까운 적에게 접근하고 보유 근접 무기의 현재 강화 사거리 안에서 감속한다. 이번 이동 의도로 접촉을 예측해 사거리 앞에서 이전 전속력 입력 때문에 회피하는 문제를 줄인다. 경험치 우선 수집, 실제 긴급 접촉 회피, 포위 돌파는 유지한다. 파이어볼의 폭발 반경은 근접 접근 거리로 쓰지 않는다.

같은 보완에서 목표 셀이 바뀔 때 유효한 공유 경로를 유지하고, 먼 적의 경로 계산이 반복 취소되는 동작을 수정했다. 고정 주기 사이 유닛 위치와 플레이어 기준 원점을 보간한다. 몬스터의 좌우 기울임·점프 보행은 없애고 정자세로 이동시키며, 피격 점멸·팽창·넉백과 플레이어 보행은 유지한다. 실제 플레이 체감과 성능 수치는 별도로 확인하며 과거 10분/30분 검사를 수정 후 측정으로 재사용하지 않는다.

## 첫 보완: 공중 무리의 퇴장

기존 모든 몬스터 보존 규칙을 공중에도 적용해 지나간 무리가 계속 쌓이던 동작을 수정했다. 화면으로 들어오는 무리는 유지하고 진행 방향으로 카메라 중심을 지나 화면 밖 여유 거리까지 벗어나면 퇴장한다. 넉백 중에는 기다린다. 퇴장 시 처치·드롭을 발생시키지 않으며 표시 풀·공간 색인·이동/FSM 기록을 회수한다. 실제 처치는 기존 보상을 유지한다. 여유 거리는 DevelopmentDefaults의 `airDepartureMargin`이다.

장시간 진단의 기준도 지상/경험치 보존과 공중 자연 퇴장으로 나눴으며 `departedAir`를 별도 기록한다. 이전 10분/30분 결과는 공중 영구 보존 규칙의 과거 측정이며 새 성능 수치로 재사용하지 않는다. 장시간 검사는 재개하지 않았다.

관련 확인만 수행했다. 소스 `6b364ef5c917c11d101e6e57a39a1ff77ce2eb5d1550686fe96cd07191d08a2b`에서 EditMode 15개(`63d41f70aea64ad39b7bb2ab5fb0ac73`), PlayMode 2개(`e98ca9f44f614e039c90587719e6cbf6`), Static(`a095d145bb124eefab0aead3fbcbb864`) 통과. 네 방향의 진입/퇴장, 여유 거리·몸 반경, 넉백, 실제 사망 보상, 지상/보스/경험치 보존, 큰 좌표·현재 카메라, 24마리 무리 전체 퇴장, 표시 풀 회수를 확인했다. 수정 전 해당 9가지 실패는 `6bee6bea86284491a383b6f1a1296006`에 남아 있다. 새 Windows 빌드와 장시간 부하 검사는 하지 않았다.
